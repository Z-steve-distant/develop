## 一、语法骨架：每一部分在哪（**位置必须能默写**）

```
[捕获列表] <模板形参>C++20 (参数列表) 修饰符序列 noexcept 属性C++23 -> 返回类型 requiresC++20 { 函数体 }
              ↓                ↓         ↓        ↓              ↓            ↓
            [x, &y]        <class T>   (int a)  mutable       noexcept      -> double
                                                 constexpr
                                                 consteval
                                    └────── 顺序在这两者之间可互换 ──────┘
```

**实测确认的位置规则**（`day1_syntax_matrix.txt` 第 1–6、26 条）：

| 写法 | 结果 |
| :--- | :--- |
| `[]() mutable -> int {...}` | ✅ |
| `[]() constexpr mutable -> int {...}` | ✅（`mutable` 与 `constexpr` 顺序可换） |
| `[]() mutable noexcept -> int {...}` | ✅ |
| `[]() noexcept mutable -> int {...}` | ❌ `expected '{' before 'mutable'` |
| `[]() -> int mutable {...}` | ❌ 同上（返回类型只能在最后） |

> 一句话记法：**`mutable` 属于"参数列表之后的修饰符"，必须排在 `noexcept` 和 `-> T` 之前。**

其他骨架细节：
- 参数列表可以整个省略：`[a] { return a; }`（无参数时等价于 `()`）——但**捕获列表不能省**，且**不能省成 `[]` 之外的东西**。
- `[] { ... }()` 是立即调用（IIFE），常用于 `const` 变量的复杂初始化。
- C++14 起 `auto` 参数（泛型 lambda）；C++20 起 `[]<class T>(T x)`（模板 lambda）。

## 二、核心：lambda 的"编译器视角"

### 2.1 展开规则（这张表就是当天的全部）

| lambda 里的东西 | 编译器生成的闭包类里的东西 |
| :--- | :--- |
| `[x]` 值捕获 | **非静态数据成员** `int x;`（在构造闭包对象时拷贝初始化） |
| `[&x]` 引用捕获 | 数据成员 `int& x;`（本质是**引用成员**，实现上是存地址） |
| `[x = expr]` init capture | 数据成员，用 `expr` **直接初始化**（C++14） |
| `[this]` | 数据成员 `Widget* this_;`（**指针**！不是拷贝对象） |
| `[*this]` | 数据成员 = **整个对象的一份拷贝**（C++17） |
| 参数列表 / 返回类型 | `operator()` 的形参和返回类型 |
| `mutable` | **`operator()` 不加 `const`**（不加 mutable 时是 `const` 成员函数） |
| `noexcept` | `operator()` 的 `noexcept` 说明符 |
| 函数体 | `operator()` 的函数体 |
| 没有捕获 | 空类 → 可隐式转换成函数指针 |

### 2.2 手写等价类（当日自检的标准答案）

```cpp
// lambda: [threshold](int v) { return v > threshold; }
struct CompareGreater {                  // ← 编译器生成的闭包类
    int threshold;                       // ← 捕获的变量成为数据成员
    explicit CompareGreater(int t) : threshold(t) {}   // ← 捕获的初始化
    bool operator()(int v) const {       // ← 非 mutable ⇒ operator() 是 const
        return v > threshold;
    }
};

// lambda: [n = 0]() mutable { return ++n; }
struct Counter {
    int n;
    Counter() : n(0) {}
    int operator()() {                   // ← mutable ⇒ operator() 没有 const
        return ++n;
    }
};
```

**实测证据**（`day1_lambda_basics.cpp` 【4】）：两者**体积相同、结果相同、const 限定相同**：

```cpp
static_assert(sizeof(decltype(lam)) == sizeof(CompareGreater));          // 都是 4
static_assert(std::is_invocable_v<const decltype(lam)&, int>);           // 闭包可被 const 调用
static_assert(std::is_invocable_v<const CompareGreater&, int>);
```

> **一句可以直接说出口的话**：lambda 表达式就是一个**匿名类**，捕获列表决定它的**数据成员**，
> `mutable` 决定 `operator()` 的 **const 限定**，调用它就是调 `operator()`；`[](){...}` 那个"调用"是在**构造一个临时对象**。

## 三、捕获列表：全部写法 + 语义 + 陷阱

### 3.1 写法清单（能默写）

| 写法 | 含义 | 关键陷阱 |
| :--- | :--- | :--- |
| `[]` | 不捕获 | 唯一能转函数指针的形式（可当 C 回调） |
| `[=]` | 隐式**值**捕获（用到的才捕获） | **成员函数里等价于捕获 `this` 指针**，C++20 已弃用隐式 this |
| `[&]` | 隐式**引用**捕获 | **悬垂的头号来源**（周二重点） |
| `[x]` `[&x]` | 显式值 / 引用捕获 | 规范推荐：**显式列出**，不用 `[=]`/`[&]` |
| `[this]` | 捕获 **this 指针** | 对象死了就悬垂（异步回调经典 bug） |
| `[*this]` | 拷贝**整个对象**（C++17） | 安全但有拷贝成本；对象大时注意 |
| `[x = expr]` | init capture（C++14） | **移动捕获**的唯一写法：`[p = std::move(q)]` |
| `[&x = expr]` | 引用型 init capture | 少见，知道即可 |
| `[=, &x]` / `[&, x]` | 默认捕获 + 显式例外 | ✅ 合法 |

### 3.2 合法性边界（**这里我原来的说法被实测纠正了**）

| 写法 | 标准 | GCC 16 实测 |
| :--- | :--- | :--- |
| `[=, &x]`、`[&, x]` | 合法 | ✅ 通过 |
| `[=, x]` | ill-formed（与默认值捕获重复） | ⚠️ **只报 warning**：`explicit by-copy capture of 'x' redundant with by-copy capture default` |
| `[&, &x]` | ill-formed | ⚠️ **只报 warning** |
| `[x, x]` | ill-formed（重复捕获） | ⚠️ **只报 warning**：`already captured 'x' in lambda expression` |

> **诚实结论**：这三种写法按标准是 ill-formed，但 **GCC 只警告不报错**（换 Clang/MSVC 可能直接拒绝）。
> 所以不要把"它编译过了"当成"它合法"——**实际编码一律避免**。
> （这类"编译器宽容度差异"正是要自己动手试才知道的东西，别背二手结论。）

### 3.3 捕获发生的**时机**

- 捕获发生在**lambda 表达式求值那一刻**（也就是定义/构造闭包对象时），不是调用时。
- 值捕获是**那一刻的快照**：定义后改原变量，闭包里不变（实测 `snapshot() == 1`，而 `alias() == 99`）。
- 引用捕获是**别名**：原变量改，闭包跟着改。

## 四、值捕获是 `const` 的，`mutable` 改的是 `operator()`

这是第一天最容易"以为自己懂了"的地方。三条实测（矩阵第 23–25 条）：

| 代码 | 结果 | 说明 |
| :--- | :--- | :--- |
| `[a]() { a = 2; }` | ❌ `assignment of read-only variable 'a'` | 无 `mutable` ⇒ `operator()` 是 const ⇒ 成员是只读 |
| `[a]() mutable { a = 2; }` | ✅ | `mutable` ⇒ `operator()` 非 const |
| `[&a]() { a = 2; }` | ✅ | **const 的是引用本身**，不是被引用的对象 |

**两个必须分清的层次**：

1. **`mutable` 不是"允许改外部变量"**——它只是去掉 `operator()` 的 `const`。
2. **`mutable` 改的是闭包内部那份副本**：实测外部 `counter` 始终是 0，而 lambda 连续调用返回 1、2、3。
   想让外部变，只能引用捕获。

**编译期判据**（可以直接写进笔记）：

```cpp
auto noMut   = [x]()         { return x; };
auto withMut = [x]() mutable { return ++x; };
static_assert( std::is_invocable_v<const decltype(noMut)&>);    // const 闭包可调用
static_assert(!std::is_invocable_v<const decltype(withMut)&>);  // mutable 闭包不可 const 调用
```

## 五、闭包对象的**类型**与**大小**

| 事实 | 实测 |
| :--- | :--- |
| 每个 lambda 表达式都有**独一无二的类型**（哪怕文本完全相同） | `static_assert(!std::is_same_v<decltype(l1), decltype(l2)>)` |
| 无捕获闭包是空类 | `sizeof == 1` |
| 大小 = 捕获到的成员之和 | `[big]`（4 个 `int` 数组）→ `sizeof == 16`；`[&big]` → `sizeof == 8`（存指针） |
| **无捕获**才有到函数指针的隐式转换 | `void(*fp)() = []{};` ✅；`[a]{}` → ❌ `cannot convert ... to 'void (*)()'` |
| lambda **不能直接递归** | `auto fib = [](int n){... fib(n-1) ...};` → ❌ `use of 'fib' before deduction of 'auto'`（要用 `std::function` 或 Y 组合子） |

**为什么"唯一类型"很重要**：两个 lambda 类型不同 → 不能直接放进同一个 `map` 当 key、不能互相赋值；
这正是**周三 `std::function` 存在的理由**——类型擦除把"千奇百怪的闭包类型"统一成一个可存储的类型。

## 六、返回类型的推导规则

- 单个 `return` → 直接推导该类型。
- 多个 `return` → **所有返回类型必须一致**，否则**编译错误**（实测原文）：

  ```
  error: inconsistent types 'int' and 'double' deduced for lambda return type
  ```
  修法：显式写 `-> double`（`day1_lambda_type_error.cpp` 里有正反对照）。
- 想要窄化/精确类型（比如整数除法要得小数），**主动写 `-> double`**，不要指望推导。

## 七、泛型 lambda 与模板 lambda（掌握要求 #3）

| 版本 | 写法 | 编译器视角 |
| :--- | :--- | :--- |
| C++11 | `[](int x){}` | 普通 `operator()` |
| C++14 | `[](auto x){ return x + x; }` | **`operator()` 本身是模板**，每个实参类型一份实例化（实测 `int` → 42，`std::string` → `"abab"`） |
| C++20 | `[]<class T>(T x){ return x * x; }` | 显式模板参数，可写出 `[]<class T>(std::vector<T>& v)` 这种需要**指名 T** 的场景（**知道即可**，W3 不深挖） |

> 注意：泛型 lambda **不是模板函数**，因为它的类型仍然是唯一的闭包类——只是那个类的 `operator()` 是模板成员。

## 九、当日自测 8 问（不看材料回答）

1. `mutable` 写在语法骨架的哪个位置？能写在 `-> int` 后面吗？
2. 一个 lambda `[x]() mutable { ++x; }`，`x` 是谁的成员？改完之后外部变量变了吗？
3. 同一个作用域里写两个文本完全相同的 lambda，它们的类型相同吗？
4. `sizeof([](){})` 是多少？`sizeof([v](){})`（`v` 是 `int`）呢？`[&v]` 呢？
5. 什么条件下 lambda 能转成函数指针？
6. 成员函数里的 `[=]` 到底捕获了什么？`sizeof` 能证明吗？
7. 多个 `return` 语句返回 `int` 和 `double`，会发生什么？怎么修？
8. 为什么 lambda 不能直接递归？

**参考答案**：1）参数列表之后、`noexcept`/`-> T` 之前，不能写在 `-> int` 后；
2）闭包自己的成员，外部不变；3）不同类型；4）1 / `sizeof(int)` / `sizeof(int*)`；
5）**无捕获**时；6）捕获 `this` 指针（`sizeof == sizeof(Widget*)`，实测 8），`[*this]` 才是拷对象（4）；
7）编译错误 `inconsistent types ... deduced for lambda return type`，显式写 `-> double`；
8）闭包类型在 `auto` 推导完成前还不可用。

## 十、常见误区（含两条"实测纠正"）

| # | 误区 | 真相 |
| :---: | :--- | :--- |
| 1 | "lambda 就是匿名函数" | 它是**匿名类对象**；有捕获就有状态、有大小、有构造 |
| 2 | "`mutable` 是让我能改外部变量" | 它只是**去掉 `operator()` 的 const**；改的永远是闭包内部副本 |
| 3 | "`[=]` 把用到的变量都拷贝了一份" | 成员函数里 `[=]` **只捕获 `this` 指针**（C++20 已弃用该隐式捕获） |
| 4 | "`[=, x]` 这种重复捕获编译器会拦住" | **GCC 只给警告**（标准是 ill-formed）——别把"能编译"当"合法" |
| 5 | "lambda 有捕获也能转函数指针" | 只有**无捕获**才行；有捕获直接编译错误 |
| 6 | "`sizeof(lambda)` 没意义" | 有意义：它就是捕获成员之和（无捕获 = 1），直接反映有没有隐藏拷贝 |
| 7 | "返回类型编译器总会推导对" | 多个 `return` 类型不一致会**直接编译失败**，要写 `-> T` |
| 8 | "`mutable` lambda 也能塞进 `const` 容器里调用" | `mutable` 闭包的 `operator()` 非 const → `const` 上下文调不了 |

## 十二、面试里这部分会怎么问

| 问法 | 一句话答法 |
| :--- | :--- |
| "lambda 的本质是什么？" | 编译器生成的匿名类；捕获 = 数据成员，`mutable` = `operator()` 的 const 限定，调用 = `operator()` |
| "值捕获能改吗？" | 不能，`operator()` 是 const 的；加 `mutable` 可以，但改的是闭包内部副本 |
| "为什么有了 lambda 还需要 `std::function`？" | 每个 lambda 类型唯一，无法放进同一个容器/接口；`std::function` 用类型擦除统一它们（代价见周三） |
| "lambda 能当 C 回调吗？" | 无捕获时可以隐式转函数指针；有捕获就不行 |
| "为什么 lambda 不能递归？" | 闭包类型在 `auto` 推导完成前不可用；用 `std::function` 或 Y 组合子 |
